# YouTube 音频文稿整理

一条 YouTube 链接 → `<YT_OUTPUT_DIR>/<标题>.docx`。判错实例、事故反例、摘要范文与各条规则的缘由见 [references/examples.md](references/examples.md)。

**铁律：用户说"总结"也要出全文。** 这仍是文稿整理任务，不是写一篇总结稿：开头放 500 字实质摘要，正文是**完整的逐字整理稿**（含时间戳、分节、高亮）。只有明确限定"只要一段摘要、不要全文"时才只写摘要，拿不准就出全文。

## 全流程

```
① yt doc <url>        下最优字幕并洗成文稿（脚本干，快）
⓪ 找现成文稿          有没有人已经整理好了？见"⓪ 先找现成文稿"
② 通读校错            识别专名误识与说话人，见"判错指南"
③ 翻译（仅非中文）     你干，不调 API —— 见"翻译硬规矩"
④ 成稿组织            写摘要、分小节、标高亮
⑤ 渲染落盘            yt render，出 docx
⑥ yt rm <video_id>    清临时文件
```

**先跑 `yt doc`**，它顺手把描述栏里的文稿链接挖出来，再决定找不找现成稿。⓪②③④ 是判断活，脚本不碰；①⑤⑥ 是确定性的。

## ① 下字幕并清洗

```bash
yt doc "<视频URL>"
```

输出告诉你：选用了哪条轨、需不需要翻译、文稿在哪、工作区在哪。选轨优先级（脚本已实现）：人工字幕·中文 → 人工字幕·视频原语言 → 人工字幕·其它语言 → 自动字幕·**仅原生语言轨**。**绝不用 YouTube 的自动翻译字幕**（原生轨以外的几百种语言都是机翻，识别误差上再叠翻译误差），翻译交给你。拿不到任何字幕时脚本明确报错（只能靠本地转录，本子技能暂不支持）。

## ⓪ 先找现成文稿

访谈、播客、大会演讲的作者常在官网发过整理稿，专名正确、说话人有名有姓、分好章节，有就拿它当底本。但检索有成本，先看值不值得：

| 情形 | 怎么办 |
|---|---|
| `yt doc` 打出了"现成文稿"候选 | **必查**。链接已经在手上，零检索成本 |
| 无候选 + 选用轨是**自动字幕** + 内容是访谈/播客/演讲 | 值得找，**检索预算 ≤3 次**，找不到就走字幕 |
| 无候选 + 已有**人工字幕** | 一般不必找；多人对话且分不清谁是谁时，值得花 1 次检索要个说话人标注 |
| 教程、vlog、新闻剪辑、音乐、中文频道 | 直接跳过，基本没有现成稿 |

**找法**（按成本从低到高，命中就停）：

1. **描述栏**：脚本已自动扫，结果在 `meta.json` 的 `transcript_candidates`，也直接打在 `yt doc` 输出里。
2. **频道官网**（`meta.json` 的 `channel_url` 或描述栏里的自有域名）：Substack 系播客（dwarkesh.com、latent.space、lennysnewsletter.com）文章页多半带全文；`lexfridman.com/<嘉宾名>-transcript`；TED → ted.com 官方交互文稿（有人工中译）；公司大会 keynote → 官方博客"remarks"（多半是 B 档）。
3. **付费墙不要翻**，去找作者自己放出来的公开副本。
4. **兜底检索**：从字幕里挑一句 8–15 词的独特句子，**加引号**搜。

**四档判定，档次决定用法**：

| 档 | 是什么 | 怎么用 |
|---|---|---|
| **A 逐字人工稿** | 带说话人名、时间戳，与字幕逐句对得上（lexfridman.com、dwarkesh.com） | **取代字幕当底本** |
| **B 编辑稿** | 明说"condensed and edited"、改写成文章体、官方博客的 keynote remarks | **只作校对参照**，正文引述仍用字幕（不是原话） |
| **C 第三方 ASR** | HappyScribe、podscripts、transcript.lol、tubetranscribe、各种"YouTube 转文字"站 | **与自动字幕同级，不是权威**；做了说话人分离才有边际价值，且必须对着字幕核 |
| **D 付费墙/残缺** | 只放前几段、要登录 | 不用 |

**用之前必验三件事**：覆盖（文稿词数 ≥ 字幕词数的 90%，低于多半是节选或被付费墙截断）；同一版本（播客音频版与 YouTube 版剪辑可能不同，抽查中段和结尾各一句）；时间戳（没有的话正文时间戳仍以字幕为准，文稿只用来正专名、分说话人）。验完在元信息块的底本说明里写清档次与来源。

```bash
# 字幕词数（拿它当分母）
grep -o '[A-Za-z][A-Za-z-]*' transcript.txt | wc -l
```

## ② 判错指南

`transcript.txt` 每段以 `[HH:MM:SS]` 时间戳开头。A 档现成文稿当底本时基本可跳过（只核对说话人切分）；人工字幕扫一遍；**自动字幕必须逐段核对**——普通词句相当准，但专名错得最狠，而且错得通顺、不引人怀疑。

1. **专名误识**（最常见，危害最大，如 Lisa Doll 实为 Lee Sedol、Opening Eye 实为 OpenAI）：凡人名、产品名、公司名、机构名、论文/书名，一律停下来问"这个东西真的存在吗、在这个语境里说得通吗"。说得通放过，说不通就查。**不确定的必须标存疑，不许猜一个填进去。**
2. **同音词错误**（`in silicon` ← `in silico`）：技术语境里的怪词优先怀疑。
3. **说话人错乱**：YouTube 自动字幕不做说话人分离，`>>` 标记稀疏且位置不可靠；人工字幕多用 `-` 标换人，只知道换人不知道换成了谁。访谈要靠语义切：谁在提问、谁在回答、谁在自述经历。第一方文稿通常直接标了说话人姓名——**哪怕字幕是人工的，为了说话人身份也值得去找一次**。
4. **多人交叉说话导致的崩溃**：现场录像、抢话片段 ASR 会彻底乱掉。**不要硬编成通顺句子**，做成独立引述块，注明"以上为语义重构"。

说话人自己说错的不算错误：**保留原文，加备注说明**，不要替他改。

## ③ 翻译硬规矩（仅当 `需翻译 = 是`）

中文字幕跳过本步，直接进 ④。中文正文在前，英文原文跟在后面用引述块 `>`：

```markdown
[00:21:26] **说话人**：中文译文。

> English original, verbatim.
```

**⚠️ 英文引述块＝逐字照录，死规矩。** 它唯一的作用是让读者核对原话，必须是底本的逐字内容。**只允许**：删掉 `uh` / `um` / `like` 这类纯填充词；合并 ASR 打散的重复（`the the the` → `the`）；补标点和大小写。**严禁**：删句、改写、压缩、合并要点、"提炼精华"——压缩过的"原话"有欺骗性，还会把说话人的否认压成认同。

**自检（写入前必做）**：成稿英文引述块总词数应达**底本**词数的 **85% 以上**（底本是字幕就对字幕数，是 A 档现成文稿就对那份文稿数）。低于这个数说明在做摘要而不是文稿，回去重做。B/C 档文稿**不进引述块**。

```bash
# 原始词数
grep -o '[A-Za-z][A-Za-z-]*' transcript.txt | wc -l
```

**中文译文中度清理**：去掉 uh/um 和重复词、补全被打散的句子，保留说话人的语气和口语节奏；目标是"一篇整理过的访谈"，不是"一篇重写过的文章"。中文同样不许漏译整句。

**备注只用来标不确定，不用来留痕**：

| 情形 | 怎么做 |
|---|---|
| 百分百确定的识别错误 | **直接改，不加备注** |
| 拿不准的 | 标红 + 备注写明存疑理由，**不替用户下判断** |
| 受访者口误（非识别错误） | 保留原文 + 备注说明（因为没改动，读者会疑惑） |
| 人物、机构的背景补充 | 可用备注，但**克制**；重要信息直接写进元信息块 |

备注即 **Word 真脚注**，写在要挂的文字后面：`存疑内容^[说明为什么存疑]`；标红：`<span style="color: #d23f31;">存疑内容</span>`。脚注挂在名字上时别把名字又写一遍（对：`嘉宾：Andrew Ambrosino^[职位]`）。

## ④ 成稿组织

- **全文摘要（必须有）**：正文之前 `## 全文摘要`，**500 字左右**。写实质内容不写元描述：单独拿给没看过视频的人，他应能知道这期讲了哪些**具体主张**。带上具体数字、人名、结论和转折，有争议或反直觉的观点优先。
- **分小节**：按话题切 `##` 并起能说清这节讲什么的标题，不用"第一部分"这种；一小时的访谈约 15-30 节。
- **关键观点高亮**：`==高亮==`（渲染成 Word 黄色高亮）标**观点、结论、反直觉的主张、具体数字**；**不标**术语、人名、产品名；**每节 1-2 处**，满篇高亮等于没有。
- **元信息块**：文档开头一个引述块，写节目/频道、嘉宾、主持人、发布日期、时长、原片链接、**底本说明**。底本说明不能省：底本是什么（第一方逐字文稿 / 人工字幕 / 自动字幕）、来源链接、做过哪些处理；用了现成文稿写出来源并注明档次，只作参照没当底本的也要说明。

## ⑤ 渲染落盘

成稿先写成 Markdown（放临时工作区即可），再渲染成 docx：

```bash
yt render <成稿.md> --title "<标题>"
```

- 产出落在成稿目录（`YT_OUTPUT_DIR`，见套件 SKILL.md），**平铺不分子目录**。
- `--title` 不给就取 md 的一级标题。
- 长文稿分批翻译时，**先把各批合成一个完整 md 再渲染**，别分多次生成 docx。

### 渲染器认的写法

宋体正文、首行缩进两字符、真脚注、标题带大纲级别（Word 导航窗格可跳转）。

| 写法 | 渲染结果 |
|---|---|
| `# 标题` / `## 小节` / `### 子节` | 大纲 1/2/3 级 |
| `> …`（文首连续几行） | 元信息块，居中楷体灰 |
| `> …`（正文中） | 引用块 |
| `[00:15:30] **说话人**：…` | 行首时间戳 + 说话人 |
| `==关键观点==` | Word 黄色高亮 |
| `^[脚注内容]` | Word 真脚注 |
| `<span style="color: #d23f31;">存疑</span>` | 红字 |
| `**粗体**` / `` `代码` `` / `[文字](url)` | 加粗 / 等宽 / 超链接 |
| `\| a \| b \|` 表格、`- ` 列表 | 表格、项目符号 |

**一段一行**：渲染器按行切段，段落中间不要软换行。数字范围不要用 `~`（会被当成脚注/删除线记号）。

## ⑥ 清理

```bash
yt rm <video_id>
```

翻译用的分批 md 如果放在别处，一并删掉。

## 交稿前自检清单

- [ ] 用户说“总结/摘要”时，交付的仍是全文文稿 + 开头摘要，不是只有一篇总结稿
- [ ] 现成文稿该找的已找过（`yt doc` 给的候选必查），用了的已定档并验过覆盖率
- [ ] 英文引述块总词数 ≥ 底本的 85%，且底本只可能是字幕或 A 档文稿
- [ ] 没有整句漏译
- [ ] 专名可疑处已核对；确定的直接改不加备注，存疑的已标红说明
- [ ] 有 500 字左右的实质性摘要，不是空话
- [ ] 关键观点已高亮，每节 1-2 处
- [ ] 元信息块含底本说明
- [ ] 数字范围未使用 `~`（会被当成脚注/删除线记号）
- [ ] docx 已生成，导航窗格能看到小节大纲，脚注编号连续
- [ ] 临时文件已清

## 排错

| 症状 | 原因与处置 |
|---|---|
| `Sign in to confirm you're not a bot` | cookies 失效。先在 Chrome 登录 YouTube；或 `YT_COOKIES_FROM=safari` |
| `HTTP Error 429` | 被限流，等几分钟 |
| `Requested format is not available` | yt-dlp 太旧。`brew upgrade yt-dlp` 或 `python3 -m pip install -U yt-dlp` |
| 文稿里出现"音乐""掌声" | 声音标记没清干净，把该写法补进 `scripts/clean.py` 的 `SOUND_TAG` |
| 段落全是 `[00:00:00]` | 时间轴在去重时丢了，检查 `dedup_rolling` 是否保留了时间 |
