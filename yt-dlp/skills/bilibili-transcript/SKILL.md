# B站视频文稿整理

一条 B站视频链接 → 可靠、可读、可追溯的 `<YT_OUTPUT_DIR>/<标题>.docx`。

## 硬边界

- 用户只说“总结”“摘要”“概括”时，仍按全文文稿流程做：开头写实质摘要，正文保留完整逐字稿；**严禁只输出一篇总结稿**。只有明确限定“只要摘要、不要全文”时才只写摘要。
- 先探测高质量现成文稿，再决定是否整理字幕。
- 只把人工 CC 或平台 AI 字幕当语音字幕；`danmaku` 是弹幕，永远排除。
- 没有可靠现成文稿且没有可用字幕时立即报告并停止。**不要下载音频，不要调用本地或云端 ASR。**
- Cookie 只从本机浏览器登录态读入内存；不得打印、导出或保存 Cookie 值。
- 现成文稿的来源与完整性必须核验，不能把第三方 ASR 聚合站当成优质底本。

## 全流程

```text
① bili doc <url>       登录探测 → 选最佳字幕 → 下载 → 清洗
② 查现成文稿           先看有没有播客版；再依据候选链接和检索式，最多检索 3 次
③ 选择底本             优质现成稿优先；否则使用人工 CC / 原生 AI 字幕
④ 整理成稿             校错、分节、高亮；字幕底本另写实质摘要
⑤ 渲染落盘             yt render，出 docx 到成稿目录
⑥ 清理工作区           用根命令 `yt rm`，移入废纸篓
```

① 是机械步骤，②—④需要判断。即使 `bili doc` 已经下载字幕，仍要完成②，不能因为“有字幕”就跳过优质文稿。

## 铁律：先问同一期有没有播客版

**B站 AI 字幕不区分说话人**，而播客平台默认分说话人；多人对谈类视频，②必须先查同一期是否有播客版。`bili probe` 给两个信号，**都只是线索，一律不要自己转线**：

| 信号 | 可靠度 | 怎么用 |
|---|---|---|
| `播客版` 行（从简介里挖出的 xiaoyuzhoufm 链接） | **确证**，挖到就是真的 | 报给用户，建议改用播客版文稿 |
| `检索 site:xiaoyuzhoufm.com "<UP主>"` | 需人工核对是不是同一期 | 自己搜一次，核对节目名与单集标题再报 |

实测（易论AI、硅谷101）简介里多半没挂小宇宙链接，真正干活的是那条检索式。**不要用小宇宙的站内搜索接口做自动判定**：那是模糊匹配（搜「歸藏」返回《三国演义·英雄局》《易经与你的关系》），拿它判命中会抓错整档节目。命中之后**停下来问用户走哪条线**，不要自己切换流程。

## ① 探测和取字幕

```bash
# 完整机械流程：探测、下载最佳字幕、生成 transcript.txt
skills/bilibili-transcript/bili doc "<B站URL>"

# 也可从套件统一入口调用
yt bili doc "<B站URL>"

# 只探测，不下载字幕
yt bili probe "<B站URL>"

# 只下载字幕，不生成 transcript.txt
yt bili subs "<B站URL>"
```

- 默认使用 Arc `Default` profile，设 `BILI_BROWSER=chrome` 改用 Chrome；Arc 的 `SESSDATA` 通过 macOS 钥匙串 `Arc Safe Storage` 解密，全程只驻留内存。**非 macOS 上 Arc 不可用，必须设 `BILI_BROWSER=chrome`。**
- 选轨：人工 CC 中文字幕 → 其它人工 CC 字幕 → 平台 AI 原生中文字幕（通常为 `ai-zh`）→ 平台 AI 原生其它语言字幕。`ai_type=1` 的 AI 翻译轨不自动采用；非中文原生字幕由 agent 通读后翻译。
- 成功后工作区：`meta.json`（视频、分P、字幕轨、文稿候选、检索式与底本风险）、`*.srt`（原始时间轴转换）、`subtitle.json`（B站字幕 JSON 原始响应）、`transcript.txt`（按段落合并、保留 `[HH:MM:SS]` 的底稿）。
- 只有弹幕、字幕元数据无 URL、或根本没有字幕轨时，命令返回非零并明确打印“没有可用字幕”，仍保留 `meta.json` 里的检索式。此时只允许完成②，找不到可靠现成稿就停。
- 字幕元数据必须走 yt-dlp 当前的 WBI 签名接口，**不要改成匿名 `/x/player/v2`**——实测可能返回其它视频的陈旧字幕 URL，造成“标题正确、正文串片”的静默错稿。

## ② 查高质量现成文稿

先读 `meta.json`：`transcript_candidates`（描述栏直接给出的候选链接，必须逐一检查）；`search_queries`（按标题、UP主、节目名生成的检索式）；`search_recommended` / `search_reason`（是否值得主动检索及原因）。

必须搜索的场景：描述栏出现“全文、文字版、实录、逐字稿、公众号、show notes”等线索；访谈、播客、对话、演讲、圆桌、讲座、口述史；字幕为平台 AI 且视频超过 20 分钟；多人对话而字幕没有说话人标注。

按 `search_queries` 最多检索 3 次，命中可信来源后停止。优先顺序：节目/UP主官网或公众号 → 联合出品方、嘉宾机构 → 明确授权转载的媒体全文。还可检查同一节目在 YouTube、播客 RSS、小宇宙等平台的描述栏（B站描述可能省略外链）。

**使用现成稿之前必须完整阅读** [source-quality.md](references/source-quality.md)（来源分档、核验方法和“张小珺商业访谈录”范例）。

## ③ 选择底本

```text
第一方/授权的完整逐字稿    → 取代字幕；保留原文结构与说话人，不再 AI 重写
第一方高质量编辑稿         → 若它就是节目正式文字版，直接作为“官方编辑稿”采用
第三方全文转载             → 只有能确认来源、版本和完整性时才采用
第三方 ASR/摘要/付费墙残文 → 不采用；回到B站字幕
```

- **采用优质现成稿**：保留原有标题、分节、说话人和正文，不另写一篇 AI 摘要替代它；文首增加来源块（节目、嘉宾、发布日期、原视频、现成稿链接、底本档次、是否完整逐字或编辑稿）；对完整稿抽查开头、中段、结尾，与视频版本不一致时退回字幕底本或明确标出删节。
- **采用字幕**：人工 CC 只需通读校错；平台 AI 字幕必须重点核对人名、机构、产品、书名、数字和说话人。确定的识别错误直接改；不确定处标红并用脚注说明（`<span style="color: #d23f31;">存疑</span>^[理由]`），禁止猜测。不删除整句，不把逐字文稿压缩成“内容摘要”。

## ④ 整理字幕底本

现成优质稿按③直接采用；只有字幕底本才执行本节。

- **文首元信息**：引述块列出节目/UP主、嘉宾、主持人、发布日期、时长、原片链接、底本说明（必须写明“人工 CC”或“B站平台 AI 字幕”、语言轨、是否参考现成稿）。
- **全文摘要**：正文前 `## 全文摘要`，约 500 字，必须包含具体主张、数字、人名、结论和转折；不写“围绕某话题进行了深入讨论”之类元描述。
- **正文**：按话题切 `##` 小节（一小时访谈通常 15—30 节）；保留 `[HH:MM:SS]` 时间戳；每节用 `==高亮==`（渲染成 Word 黄色高亮）标 1—2 个关键观点，不高亮单纯术语或人名；中文字幕不翻译，非中文字幕以中文在前、原文引述块在后，原文不得压缩或改写。

## ⑤ 渲染落盘与 ⑥ 清理

成稿先写成一个完整的 Markdown（放临时工作区），再渲染：

```bash
yt render <成稿.md> --title "<标题>"
```

产出落成稿目录（`YT_OUTPUT_DIR`），**平铺不分子目录**；长文分批整理时**先合成一个完整 md 再渲染**；渲染器认的写法见 [youtube-transcript](../youtube-transcript/SKILL.md#渲染器认的写法)，两个子技能共用同一套。确认 docx 无误后：

```bash
yt rm <BV号或视频URL>
```

该命令把任务工作区移入废纸篓，可恢复；不得用 `rm -rf`。

## 交付检查

- [ ] 用户说“总结/摘要”时，交付的仍是全文文稿 + 开头摘要，不是只有一篇总结稿
- [ ] 使用有效登录态探测，未把弹幕当字幕
- [ ] 描述栏候选已检查；应搜索的访谈/播客已完成最多 3 次检索
- [ ] 现成稿已核验来源、版本、完整性并标明档次
- [ ] 无现成稿且无字幕时已停止，没有下载音频或调用 ASR
- [ ] 字幕底本有实质摘要、分节、时间戳、高亮和专名校对
- [ ] docx 已生成，导航窗格可见小节大纲、脚注编号连续，文首写明底本与来源
- [ ] Cookie 从未落盘或输出
- [ ] 临时工作区已移入废纸篓

## 排错

| 症状 | 处理 |
|---|---|
| `Arc 中没有有效的 B站登录 Cookie` | 在 Arc 登录B站后重试；或设置 `BILI_BROWSER=chrome` |
| `find-generic-password failed` | 解锁登录钥匙串，并确认存在 `Arc Safe Storage` |
| 只看到弹幕 | 登录态无效或视频确实无字幕；以 `meta.json` 的 `subtitle_tracks` 和错误类型为准 |
| 字幕有语言名但 URL 为空 | 视为不可用字幕，不能假装成功 |
| HTTP 412/风控 | 停止并稍后重试，不循环轰炸接口 |
| 分P取错 | 在 URL 保留 `?p=N`，工作区会写成 `<BV号>_pN` |
