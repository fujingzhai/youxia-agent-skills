# 知网抓取：实现原理、版式规格与开发备忘

SKILL.md 只留使用规则；本文是通道选择的原因、版式与台账规格、改代码前必看的坑，以及批量提取正文的写法。

## 为什么只走 AI 阅读通道

知网三个全文入口，只有一个能自动化：

| 入口 | 实况 |
|---|---|
| 「HTML阅读」按钮 | 跳 `bar.cnki.net`，**中文点选码**（"请依次点击：报 部 拌"，AI 生成背景），无头过不去。这是唯一撞码的入口 |
| 「PDF下载 / CAJ下载」 | **能直接下，无验证码**。搜索结果行 `a.downloadlink`，详情页 `.btn-dlpdf` / `.btn-dlcaj`（注意不是 a 标签）。需 `accept_downloads=True` |
| 「CNKI AI阅读」 | **零验证码**，`ai.cnki.net/trans?path=study&cid=…&mimetype=XML`，正文在 `div.ChapterWrap.Content` |

检索页另有一道拼图滑块（AJ-Captcha），`lib/captcha.py` 用 Canny 边缘 + 模板匹配定位缺口，配合先加速后减速的仿真轨迹拖动，一次通过。**这道能破，点选码那道不碰。**

流程：检索 → 知网节详情页（取刊期、页码、DOI、作者单位）→ AI 阅读页（取正文）。

2026-10-08 起默认只下原版 PDF，`--docx` 才出 DOCX——多数文章不值得两份，PDF 作正本已够。下面是出 DOCX 时仍连 PDF 一起下的缘由：知网 XML 有三个 DOCX 侧无法弥补的缺陷——表格图的字会被替换（实测「苏辙」成了「q 辙」，PDF 里正常）、偶尔漏标脚注、整篇 XML 会消失（《楚辞早期官方传播》昨天还能抓，隔天就取不到了）。反过来，XML 随时可能消失，能抓时抓下来是零成本的保险。

## 生僻字图为什么要两步取

字形图 URL 带**一次性 nonce**：页面渲染用掉后，事后再 GET 只会拿到 `{"code":706}`。但页面又不会去请求每一个字形图——约两成从不发请求，那些 nonce 反而还新鲜。所以：

1. 加载页面时监听响应，把浏览器请求到的图 body 收下（占约八成）；
2. 对页面没请求过的，事后直接 GET（正好能取到），失败重试三次。

两步互补，实测 87 个字形图能收齐 86 个。图片按**在正文中的序号**匹配，不按 URL——URL 每次加载都变，序号不变。

## 检索细节

**繁简实测**（某位吴姓作者，三字姓名）：

| 检索词 | 结果 |
|---|---|
| 全简 | 4 条 |
| 全繁，姓作「吳」 | **0 条** |
| 姓仍作「吴」，名用繁体 | 3 条 |

原因不在姓名位置，而在**国家的繁体字形规范**：有些字的规范繁体就是那个简体字形，「吴」的繁体正字仍是「吴」不是「吳」。所以在当前规范下，吴姓作者的全繁写法姓氏仍作「吴」，opencc 的 s2t 给出的「吳」反而不合规范，一条也查不到。假如名字叫「冯吴」，要查繁体文章就得用「馮吴」而非「馮吳」。这类字不多，但无法预先穷举。

**翻页**：`.search-page` 里的 `<em>` 不是总页数（6327 条的刊也显示 10），据此判停会让每次检索空翻 40 页。

**无结果**：页面是 `#briefBox p.no-content`「抱歉，暂无数据，请稍后重试」，1 秒内出现，且有结果的页面加载中不会先闪它。2026-10-08 前选择器是猜的（`.noresult` 等全不对），无结果白等 20 秒后报成「页面未在时限内加载完整」，曾误导 agent 去查网络、读源码。现在结果与空提示一起等。

## 输出规格

**版式**（各刊统一）：

| 部位 | 格式 |
|---|---|
| 来源行 | 《文史》2026年第1期，第5—27页　五号 居中；用字随正文繁简 |
| DOI | 第二行　五号 居中 |
| 文章标题 | 小二 18pt 粗 居中（Heading 1） |
| 作者（单位） | 五号 居中；多作者时单位另起一行；有作者简介则挂星号脚注 |
| 摘要、关键词 | 同正文（小四 1.5 倍 首行缩进 2 字），末段留 18pt 余白 |
| 一级标题 | 三号 16pt 粗 居中（Heading 2） |
| 二／三／四级 | 四号 14 / 小四 12 / 小四 12，左对齐（Heading 3–5）；四级不小于正文 |
| 正文 | 小四 1.5 倍行距，首行缩进 2 字，两端对齐；默认使用 STSong（宋体） |
| 表题图题、参考文献 | 五号，比正文小一号；表格内文字小五 |
| 脚注 | 小五 单倍 两端对齐，**真·页下脚注**，全篇连续编号 |
| 页面 | A4，上下 2.54cm 左右 3.17cm |

全宋体。标题用内置 Heading 样式，**导航窗格可跳转**（Word for Mac：视图 → 侧边栏 → 导航）。

**繁简以正文为准**。字段名（关键词/關鍵詞）自动跟随；来源行也跟随——知网元数据一律简体，《中國經學》《諸子學刊》这类繁體刊物照抄下来就成了简体刊名压在繁體正文上头，所以整条转写（opencc `s2t`）。代价是繁體排印、刊名却登记为简体的刊物（如《历史文献研究》）也会写成《歷史文獻研究》。判据是这一行属于文档自身的行文，不是著录用的刊名原形；要给某刊钉死写法，在 `docx_builder._cc` 前加一张刊名对照表即可。

**首部只留中文**：英文题名、英文作者、英文摘要一律丢弃。丢掉的原文会记进验收报告的 `dropped`，逐字核查据此放行，不会误报缺文。

**星号脚注**（自定义标记，不占数字序列，正文注从 id=3 起）：基金挂题名（`*`）；各刊自带的「作者：」简介挂作者行——只有基金时用 `*`，两者都有时用 `**`。刊物没给简介就不出注，不拿元数据硬凑。

**图分两类**：长在段落文字里的是**生僻字图**（Unicode 装不下的字，知网用小 jpg 顶替，约 60px），按正文字号行内嵌入；独立成块的是**表格／插图**（`class=zoomImg`，在段落外的 `div` 里），独立成段居中、按版心宽度 14.6cm 等比缩放。表题「表1」居中加粗且不入大纲。两者都走同一个 attachment 接口，只能靠「在不在段落里」区分。

**原生表格与验收**：XML 中的 `table` 按行列写入 DOCX 表格，保留表题、单元格文字、跨行跨列和格内字形图；转换后更新总表 `抓取记录.csv`，不再生成逐篇 `.quality.json`。验收核对 DOCX ZIP、脚注引用、表格数量、缓存正文文本和图片数量。

**统一抓取台账**字段：篇名、作者、刊物、年份期号、DOI、来源链接、DOCX/PDF/CAJ 相对路径、原版状态、验收状态、问题说明、时间和校验值；完整原始验收信息保存在「验收详情」单元格。

**尾注转脚注**：有的刊用编号制尾注（正文 `[1](P349)`，条目在 `div.references-box`）。落盘时就地转成页下脚注，注文＝该条著录＋该处页码，同一文献被引十几次就是十几条各带页码的注，著录格式沿用原刊。**注意** `a[type=reference]` 知网两种体例共用：编号制是 `<sup><a>[1]</a></sup>`，著者年制夹注是 `<citation><a>丁四新，2006</a></citation>年，第43页)`，后者本身可读，必须原样保留——按数字粗暴匹配会把「2006」当编号，整条夹注就没了。

**汉字间的游离空格**：知网 XML 自带（原刊字距／换行的转换残留，如「义俭辞 碎」「文 心雕龙」），落盘时清掉。只删汉字与汉字之间的，中英之间、数字两侧一律保留。

**脚注漏标实例**：王尔《智论框架中的「素相」构想》（《中国哲学史》2026-3）PDF 原刊 4 条注，知网 XML 只标了 2 条。

## 几条踩过的坑（改代码前先看）

1. **别拿固定 `sleep` 当状态判据**。`wait_for_timeout(12000)` 之后直接读 DOM，页面慢一拍就会误判成「无结果」「无 XML 正文」——曾据此错误断言「知网 XML 会消失」。一律用 `wait_for_selector` 等元素真的出现。同理，翻页判停也不能靠「本页不足 20 条」。
2. **三个全文入口互不相同**：「HTML阅读」撞点选码，「下载」和「PDF下载」直接下、无验证码。别因为一个撞码就否定另外两个。
3. **`a[type=reference]` 两种体例共用**：编号制 `<sup><a>[1]</a></sup>` 要转脚注，著者年制 `<citation><a>丁四新，2006</a></citation>` 必须原样留着。
4. **图分两类**，靠「在不在段落里」区分，尺寸逻辑完全不同。
5. **内部标记别用 `\u0000`**，残留时 python-docx 拒收 NULL 字节；用 `\ufff9`。
6. **别并发**。cloakbrowser 免费版单会话，两个实例抢 profile 直接崩，已加 `.lock` 互斥。
7. 报「无结果」但确实有：早期版本用固定 sleep 等页面，慢一拍就误报；现已全部改成 `wait_for_selector`，若再遇到，检查是不是新加的代码又用了 `wait_for_timeout` 当状态判据。

## 以后要批量提取正文（做知识库等）

**脚注不在 `paragraph.text` 里**。实测《先秦盟、詛關係》：段落文本 19779 字，另有 4818 字注文只存在于 `word/footnotes.xml`。只读段落 = 124 条注全丢，而版本、卷次、页码全在注里。多读一个部件即可：

```python
import zipfile, re
from docx import Document
d = Document(f)
body  = [p.text for p in d.paragraphs]                        # 正文
notes = zipfile.ZipFile(f).read('word/footnotes.xml').decode()  # 注文
# 注文按 <w:footnote w:id="N"> 切开，id=1 基金星号注、id=2 作者简介注，3 起对应正文第 1、2… 条
```

正文与注的**对应位置**在 docx 里要靠 `w:footnoteReference w:id` 回溯。如果需要「哪句话挂哪条注」，直接从 `cache/*.html` 取更省事——那里 `sup.footNote[footnotetitle]` 就长在它所属的位置上，是 docx 的上游。

## 目录

```
cnki                 入口脚本（可软链到 PATH）
.env                 本机设置（CNKI_OUTPUT_DIR 等），模板见 .env.example
.lock                并发互斥锁（cloakbrowser 免费版只能开一个会话）
lib/fetch.py         检索、元数据、正文、CLI
lib/search.py        列表检索（作者/来源/主题、分面、翻页）
lib/captcha.py       拼图滑块
lib/docx_builder.py  排版（版式常量都在文件头）
lib/footnote.py      页下脚注注入（python-docx 没有脚注 API，手工写部件）
lib/quality.py       DOCX ZIP、表格、图片、脚注和缓存文本的本地验收
lib/records.py       统一 CSV 台账、校验值与续抓判断
lib/network.py       验证码/限流/权限的暂停条件与有限等待
profiles/cnki/       登录态，勿删
cache/               HTML 与图片缓存，--cache 重排用
待抓.md               批量清单（--to-list 写入，-f 默认读取）
待手工下载.md          无 HTML 全文的回退清单（自动生成）
```
